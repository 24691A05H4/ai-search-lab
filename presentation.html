Project Overview & Objectives
🎯 The Academic Problem
  • Most student game projects treat Minimax as an opaque "black box".
  • Minimax scales exponentially: O(b^d). For large games (Chess, Checkers), unconstrained search is computationally impossible.
  • Real-world games mandate Depth Limits and Domain Heuristics.
  • Goal: Build an interactive research testbed that allows students and researchers to visualize tree growth, heuristic cutoffs, and latency in real time.
✨ Key Deliverables
  • Interactive 3×3 Arena: Human ('X') vs AI ('O') with winning line highlights.
  • Adjustable Search Depth (1 to 9): Transition from naive heuristic play to game-theoretic perfection.
  • Live Telemetry: Accurate tracking of nodes generated, cutoff nodes, and latency (ms).
  • Multi-Depth Benchmark: Empirical test of Depths 1–9 on identical board states.
  • Zero-Dependency Design: Custom HTML tables replacing pyarrow for 100% stability.

Adversarial Search
Depth-Limited Minimax Algorithm
🧠 Recursive Search Logic
  • Maximizing Turn (AI 'O'): Computes max(eval, best_score).
  • Minimizing Turn (Human 'X'): Computes min(eval, best_score).
  • Terminal Utility Function:
    • Win for AI: +(100 - current_depth) (rewards faster wins).
    • Win for Human: -(100 - current_depth) (penalizes quick losses).
    • Draw: 0.
  • Depth Cutoff Condition: If current_depth >= max_depth and game is non-terminal, halts recursion and evaluates heuristic score.
  • O(1) Memory Backtracking: Executes undo_move() in constant time.
📊 Complexity & Growth
  • Time Complexity: O(b^d) where b is the branching factor (up to 9) and d is the chosen depth limit.
  • Space Complexity: O(d) recursion stack memory.
  • Node Expansion Scaling:
    • Depth 1: Explores only 9 nodes (~0.07 ms).
    • Depth 5: Explores 8,081 nodes (~38 ms).
    • Depth 9: Explores 59,705 nodes (~142 ms).
  • Theoretical Unbeatability: Depth 9 conducts full game-tree search and cannot be beaten.
State Evaluation
Domain-Specific Heuristic Function
1. Line Threat Analysis

Evaluates all 8 winning lines (3 rows, 3 columns, 2 diagonals):

  • +10 points: 2 AI pieces ('O') + 1 empty
    (Imminent winning opportunity)
  • +1 point: 1 AI piece ('O') + 2 empty
    (Open offensive lane)
  • -10 points: 2 Human pieces ('X') + 1 empty
    (Urgent defensive block required)
  • -1 point: 1 Human piece ('X') + 2 empty
  • 0 points: Blocked lines containing both 'X' and 'O'
2. Positional Control Matrix

Assigns geometric value based on winning line participation:

  • Center Cell (Cell 4): ±3 points
    Participates in 4 winning lines (Row 2, Col 2, and both Diagonals). Highest tactical priority.
  • Corner Cells (0, 2, 6, 8): ±2 points
    Each corner participates in 3 winning lines (1 Row, 1 Col, 1 Diagonal). Key for creating forks.
  • Edge Cells (1, 3, 5, 7): ±1 point
    Participates in only 2 lines (Row & Col). Lowest tactical flexibility.

System Engineering
Engineering Challenges & Solutions
1. PyArrow Missing on Windows ARM64
  • Issue: Streamlit's st.dataframe() crashed with ModuleNotFoundError: No module named 'pyarrow' because PyPI lacks prebuilt ARM64 wheels for Python 3.13.
  • Solution: Built render_styled_table() using pure HTML/CSS through pandas .to_html(). 100% stable across all architectures.
2. Asyncio WinError 10054 Socket Error
  • Issue: Python 3.13's default ProactorEventLoop threw WinError 10054 upon client browser refreshes.
  • Solution: Set asyncio.WindowsSelectorEventLoopPolicy() on Windows at startup to eliminate dropped socket crashes cleanly.
3. Streamlit Session State Management
  • Issue: Streamlit reruns scripts from top to bottom on every user click, risking loss of ongoing game board state.
  • Solution: Encapsulated game engine, move telemetry, and history inside st.session_state.
4. Streamlit 1.66 Deprecation Migration
  • Issue: use_container_width=True was deprecated in Streamlit 1.66.
  • Solution: Updated button parameters to width="stretch" and modern styling standards.

❓ Typical Viva Questions & Answers
  • Q: Why are there 0 cutoffs at Depth 9?
    A: Because every branch reaches a terminal state (win, loss, or draw) within 9 moves. The heuristic is never triggered.
  • Q: Why Depth-Limited Minimax over Alpha-Beta Pruning?
    A: Alpha-Beta prunes nodes based on bounds. Depth-Limited Minimax was specifically chosen to measure raw tree expansion and heuristic behavior.
  • Q: What is the branching factor?
    A: At root: 9. Decreases by 1 at each ply down to 1 at leaf nodes.
